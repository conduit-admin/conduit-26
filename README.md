# Кондуит

Учёт плюсов на математической смене: кондуиты по дням, общий рейтинг и
пересчёт рейтинга по любому подмножеству серий и тем.

Сайт открывается по ссылке, читать может кто угодно, писать — только владелец
репозитория. Никакого сервера и базы данных нет: страница читает файлы из
`data/` и считает всё в браузере читателя.

## Как считаются баллы

Вес задачи = **n − число решивших её**, где n по умолчанию равно числу учеников
на смене. Задача, которую сдали трое из двадцати четырёх, стоит 21 балл; задача,
которую сдали все, — 0.

Само n задаётся во вкладке «Очки» редактора и лежит в `data/config.json`
(`scoring.n`). Поднять его выше числа учеников имеет смысл, если даже задачу,
взятую всеми, не хочется обнулять: при n = 30 такая задача стоит 6. Ниже числа
учеников n не опускается: вес ушёл бы в минус, и плюс отнимал бы очки.

Вес зависит только от самой задачи, поэтому при любом фильтре баллы за неё не
меняются и рейтинги сопоставимы между собой.

Порядок в рейтинге: сначала очки, при равенстве — по алфавиту. Место у каждого
своё, одинаковых мест не бывает.

В кондуите — и на сайте, и в редакторе — ученики стоят по алфавиту: там ищут
человека, а не место. Сравнивается полное имя, поэтому однофамильцы идут по
именам.

## Что где лежит

```
index.html          страница: рейтинг, кондуиты, карточка ученика
edit.html           редактор: ввод кондуита с телефона
assets/             стили и скрипты
data/
  config.json       название смены, число учеников
  types.json        темы: разделы и подразделы
  students.json     список учеников
  graves.json       гробарий: задачи вне серий
  series/NN.json    кондуит одного дня
  series/manifest.json  список файлов серий
tools/build.py      сборка offline.html — копии сайта одним файлом
offline.html        снимок сайта одним файлом: открывается без интернета
```

## Формат серии

```json
{
  "n": 7,
  "series": 5,
  "date": "2026-08-03",
  "kind": "series",
  "problems": [
    { "id": "0", "type": "algebra", "sub": "inequalities", "exercise": true },
    { "id": "1", "type": "comb", "sub": "graphs", "exercise": false },
    { "id": "2а", "type": "numbers", "sub": null, "exercise": false }
  ],
  "solved": {
    "ivanov-artem": ["1", "2а"],
    "petrova-masha": []
  }
}
```

`kind` — что было в этот день: `series` (по умолчанию), `off` — выходной,
`battle` — математический бой. Выходной и матбой задач не несут: в фильтрах
рейтинга их нет, в списке дней они видны, чтобы был виден ритм смены.

Номер есть только у дня с серией, и это номер самой серии — `series`. Выходной
и матбой номеров не занимают, поэтому серии нумеруются подряд; в списке дней
они помечены буквой: **В** — выходной, **М** — матбой. Дни идут по датам.

`n` — служебный слот: он же имя файла (`07.json`) и ключ дня внутри редактора.
Наружу он не показывается и меняться не должен. У файлов, записанных до
разделения, отдельного поля `series` нет — там номером серии служит `n`.

Единица зачёта — задача целиком или её пункт (`5а`, `5б`): у каждой свой вес.
`type` — раздел из `types.json`, `sub` — подраздел; `null` только у разделов
без подразбиения.

Если подраздел задачи отсутствует в `types.json` — например, его удалили —
задача остаётся **без темы**: в рейтинг она не идёт, пока ей не выберут тему
заново. В кондуите она при этом видна, но с серой полоской вместо цветной, а в
редакторе помечена серым кружком и вопросом вместо названия подраздела.

`exercise` — вид задания, признак, не связанный с темой. Упражнение узнаётся по
номеру: числовая часть номера равна нулю (`0`, `0а`, `0б`) — значит упражнение.
Поле лишь повторяет это в файле; правило одно и то же на сайте и в редакторе. Отдельно ставить его негде и не нужно. На сайте
упражнения фильтруются отдельно: в рейтинге есть переключатель «Что считаем —
задачи / упражнения».

## Гробарий

Особо сложные задачи, которые копятся всю смену и не привязаны ко дню. Номер
всегда `Гn`, живут в `data/graves.json`:

```json
{
  "problems": [
    { "id": "Г1", "type": "geometry", "sub": "stereometry" },
    { "id": "Г2", "type": "comb", "sub": "graphs" }
  ],
  "solved": {
    "ivanov-artem": ["Г1"],
    "petrova-masha": []
  }
}
```

Вес считается той же формулой, поэтому гроб, который взял один человек, стоит
почти в цену смены. В рейтинге у гробов свой переключатель — их видно и без
них. Отбор по сериям на них не действует: дня у них нет, поэтому «ни одной
серии» плюс включённые гробы даёт рейтинг по одному гробарию.

## Редактор

`edit.html` на том же сайте — страница ввода. Открывается в браузере телефона,
сервера не требует: правки уходят прямо в этот репозиторий через GitHub API,
а сайт после коммита выкладывается сам.

Что нужно один раз: вкладка **Доступ** → вставить fine-grained токен с доступом
только к этому репозиторию и правом **Contents: Read and write**. Токен лежит в
localStorage браузера и уходит только на `api.github.com`. Если телефон
потерялся — отозвать токен в настройках GitHub.

Черновиков на диске нет: правки живут в памяти страницы и уходят в репозиторий
по кнопке во вкладке «Сохранение». Уход со страницы их теряет, ничего не
переспрашивая; переключение между днями — нет.

Редактор и сайт независимы: это две разные страницы, переходов между ними в
интерфейсе нет.

- **Дни** — лента дней по датам; «+ день» заводит новый и сразу ставит его в
  ленту, как подраздел в темах. В репозиторий он уедет позже, из вкладки
  «Сохранение». У дня задаются дата и что в нём было (серия, выходной, матбой),
  у серии — ещё и номер, а также список задач с темами и сетка
  «ученики × задачи». Правки каждого дня живут отдельно: переход на другой день
  ничего не теряет. Касание клетки ставит и снимает плюс. Внизу видно, сколько
  человек решило каждую задачу и сколько она стоит. Там же кнопка удаления дня.
- Удаление — везде два нажатия: крестик раздваивается на «удалить» и
  «передумал», и так же спрашивает кнопка удаления дня. Словами это не
  поясняется: второе нажатие и есть предупреждение.
- Только что удалённый день стоит в ленте запертым, как только что
  сохранённый, и уходит из неё сам, когда сайт переразвернётся.
- **+ задача** первым нажатием даёт упражнение — номер `0`, дальше номера идут
  подряд. Если упражнения в этот день нет, номер правится вручную.
- **+ пункт** превращает задачу `5` в `5а` и добавляет `5б`; плюсы при
  переименовании не теряются. Пунктов не больше шести: после `е` кнопка
  выключается — следующий пункт совпал бы с уже существующим.
- **Гробы** — тот же список и та же сетка, но без дат и номеров: «+ гроб» даёт
  следующий свободный `Гn`, тема выбирается так же, как у задачи серии.
- **Темы** — разделы и подразделы: добавление, удаление. Правка сразу доступна
  при разметке задач, но в репозиторий не уходит, пока не нажата кнопка; уже
  записанные серии не меняются. Удаление спрашивает дважды: задачи удалённого
  раздела или подраздела останутся без темы и выпадут из рейтинга, пока им не
  выберут тему заново — вкладка «Сохранение» покажет их списком. Раздел уходит
  вместе с подразделами, а его цвет возвращается в набор свободных. Последний
  раздел удалить нельзя: задаче нужна тема, а взять её было бы неоткуда.
- Там же, в разделе «Очки», задаётся n из формулы веса. Правка сразу видна в
  строке весов под кондуитом, а в репозиторий уходит по кнопке сохранения.
- В самом низу вкладки «Сохранение» стоит маленький переключатель.
  Включённый и сохранённый, он приписывает внизу карточки одного ученика
  полупрозрачную строку. Всё про неё — в `data/config.json`, в `signature`:
  `on` (это и есть переключатель), `student` и `text`. Файл перед записью
  перечитывается, и меняется в нём только то поле, которое правили: иначе
  правка одной настройки откатывала бы чужое изменение другой.
- **Сохранение** — единственное место, откуда что-либо уезжает в репозиторий, и
  там же токен. Добавление и удаление дня до этой кнопки меняют только экран
  редактора. Одна кнопка отправляет всё накопленное: темы, затем записанные дни,
  затем удаления, затем гробарий, и последним — одной записью — список дней.
  Между сохранениями две минуты перерыва, отметка лежит в localStorage, поэтому
  перезагрузка её не обходит. Рядом кнопка отката — она выбрасывает все правки и
  возвращает то, что на сайте. Если у каких-то задач подраздела больше
  нет, вкладка показывает их списком: они не считаются, пока им не выберут тему
  заново.
- Только что сохранённый и только что удалённый день заперты, пока Pages не
  переразвернёт страницу: иначе первый можно было бы создать заново поверх
  сохранённого, а второй — открыть и вернуть, отменив удаление.

## Чтобы сайт нельзя было положить из редактора

Чинить сайт посреди смены некому, поэтому редактор устроен так, что испортить
данные им нельзя даже при сбое связи или правке с двух устройств сразу.

- **Список дней не считается по памяти страницы.** При каждом сохранении он
  берётся из самой папки `data/series` (GitHub отдаёт её содержимое), а к нему
  добавляется только что записанное и вычитается только что удалённое. Поэтому
  любое прошлое расхождение — строка без файла или файл без строки — уходит при
  ближайшем сохранении само, даже если о нём никто не помнит.
- **Пустой список не пишется никогда**: если дни не удаляли, а считать нечего,
  сохранение отменяется с ошибкой — так выглядит сбой ответа, а не правка.
- **Чужой файл не переписывается.** День, о котором редактор не знает, но файл
  под его именем в репозитории есть, — это всегда чужие данные (список не
  прочитался, страница открыта со старым). Запись отклоняется с просьбой
  обновить страницу.
- **Непрочитанное не правится.** Если список дней или гробарий не загрузились,
  соответствующая вкладка показывает не пустой список, а сообщение: пустой
  экран, уехавший в репозиторий, стёр бы настоящие данные.
- **Настройки пишутся по одному полю** — то, которое правили. Значение
  нетронутого берётся из файла, а не из памяти страницы.
- **Сайт переживает порчу данных.** Пропавший файл дня пропускается, пропавший
  или испорченный список дней — тоже: страница откроется без дней, но откроется.

Чего редактор пока не умеет: работать при полностью отсутствующем интернете
(страница не закеширована, нужен service worker) и править список учеников.

## Как обновляется сайт

Любое изменение файлов в ветке `main` GitHub Pages выкладывает сам, обычно
меньше чем за минуту. Отдельной кнопки «опубликовать» нет.

Офлайн-копия — снимок на момент сборки, её надо пересобирать вручную:

```
python tools/build.py
```
